# Каталог скиллов и промптов Klodex

Официальный открытый репозиторий расширений, методологий и шаблонов для автономного AI-кодинг агента [Klodex](https://github.com/lonestill/klodex).

Все расширения отсюда попадают во встроенный маркетплейс Klodex и устанавливаются пользователями в один клик.

---

## Архитектура расширений: Скиллы vs Промпты

Klodex строго разделяет расширения на **Скиллы** (поведенческие правила и регламенты) и **Промпты** (шаблоны задач и слеш-команды).

```text
klodex-skills/
├── registry.json                 # Индекс каталога, считываемый клиентами Klodex
├── skills/                       # Полноценные модули поведения и методологий
│   └── <skill-id>/
│       └── SKILL.md              # Манифест и правила скилла
└── prompts/                      # Шаблоны задач и слеш-команды
    ├── system/                   # Системные роли (настройка мышления агента)
    ├── user/                     # Пользовательские шаблоны (/explain, /test)
    └── composite/                # Гибридные шаблоны (роль + действие в чат)
```

---

## 1. Скиллы (`skills/<id>/SKILL.md`)

Скилл — это свод правил, ограничений и методологий. Агент активирует скилл автоматически, когда задача пользователя совпадает с триггерами (`triggers`), либо держит его включённым всегда (`always_active: true`).

### Структура файла `skills/<id>/SKILL.md`

Скилл оформляется в виде Markdown-файла с YAML-шапкой (Frontmatter):

```markdown
---
name: "Clean Architecture Guard"
description: "Контроль границ слоев архитектуры, Dependency Inversion и изоляции доменной логики."
category: "architecture"
version: "1.0.0"
author: "your-github-username"
triggers:
  - "архитектура"
  - "чистая архитектура"
  - "clean architecture"
  - "слои"
tags:
  - "architecture"
  - "solid"
  - "ddd"
always_active: false
---

# Инструкции для агента

Ты выступаешь в роли архитектурного надзирателя. При любом проектировании или изменении кода следуй жестким правилам:

1. **Доменный слой чист**: Сущности и use-case не импортируют внешние библиотеки (базы данных, HTTP-фреймворки).
2. **Инверсия зависимостей**: Домен определяет интерфейсы (порты), инфраструктура реализует их (адаптеры).
3. **Никаких сквозных утечек**: DTO из HTTP-контроллеров не должны попадать напрямую в сущности базы данных.
```

### Поля манифеста скилла:

| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `name` | `string` | Человекочитаемое название в каталоге |
| `description` | `string` | Краткое описание назначения скилла (1–2 предложения) |
| `category` | `string` | Категория: `architecture`, `code`, `security`, `ops`, `writing`, `testing`, `tools` |
| `version` | `string` | Семантическая версия расширения (например, `1.0.0`) |
| `author` | `string` | Автор или GitHub username |
| `triggers` | `string[]` | Фразы и ключевые слова, при встрече которых в чате скилл активируется |
| `tags` | `string[]` | Теги для поиска и фильтрации в UI |
| `always_active` | `boolean` | `true` — инструкции скилла подмешиваются в каждый запрос агента без ожидания триггеров |

## 2. Промпты (`prompts/<type>/<id>.md`)

Промпты созданы для быстрой автоматизации типовых операций. Они делятся на **три типа**:

### Тип A: `system` (Системный режим)
Задаёт роль, специализацию и тон агента на уровне системного промпта.
- **Путь:** `prompts/system/<prompt-id>.md`

```markdown
---
id: "strict-code-auditor"
name: "Strict Code Auditor"
type: "system"
category: "code"
version: "1.0.0"
author: "your-name"
description: "Режим бескомпромиссного ревью кода: поиск гонок, утечек памяти и оверинжиниринга."
tags: ["review", "performance"]
---

Ты — Principal Systems Engineer с 20 годами опыта в высоконагруженных системах.
Твоя задача — проводить беспощадный аудит кода.
- Никакой похвалы и вежливой воды. Сразу суть.
- Каждое замечание должно указывать конкретную строку, сценарий падения и исправление.
```

---

### Тип B: `user` (Пользовательский шаблон / Слеш-команда)
Регистрирует команду (например, `/explain-arch`). При вызове вставляет готовый текст вопроса в поле ввода чата.
- **Путь:** `prompts/user/<prompt-id>.md`

```markdown
---
id: "explain-architecture"
name: "Explain Architecture"
type: "user"
slash: "/explain-arch"
category: "architecture"
version: "1.0.0"
author: "your-name"
description: "Глубокий анализ архитектуры открытого проекта с построением Mermaid-диаграммы."
tags: ["diagram", "architecture"]
---

Проанализируй архитектуру текущего проекта в рабочей директории:
1. Выдели ключевые модули и ответственность каждого слоя.
2. Опиши потоки данных между сервисами/компонентами.
3. Построй наглядную Mermaid-диаграмму зависимостей (`graph TD`).
```

---

### Тип C: `composite` (Гибрид: Роль + Слеш-команда)
Самый мощный тип промпта. Содержит две секции, разделенные HTML-комментариями `<!-- system -->` и `<!-- user -->`.
При вызове слеш-команды (например, `/deep-audit`) он **одновременно** временно настраивает системную роль агента и отправляет структурированный запрос от пользователя.
- **Путь:** `prompts/composite/<prompt-id>.md`

```markdown
---
id: "deep-audit"
name: "Deep Security Audit"
type: "composite"
slash: "/deep-audit"
category: "security"
version: "1.0.0"
author: "your-name"
description: "Комплексный аудит безопасности: активирует режим AppSec-офицера и запускает проверку кода."
tags: ["security", "audit", "owasp"]
---

<!-- system -->
Ты — ведущий инженер по информационной безопасности (Application Security Specialist).
Ты проверяешь кодовую базу на уязвимости OWASP Top 10, инъекции, небезопасную десериализацию и утечки секретов.

<!-- user -->
Проведи полный аудит безопасности проекта:
1. Просканируй точки входа внешних данных (API роуты, парсинг пользовательского ввода).
2. Проверь работу с БД и внешними командами (SQLi, Command Injection).
3. Проверь аутентификацию, авторизацию и обработку токенов/сессий.
4. Выведи список уязвимостей с оценкой критичности (Critical / High / Medium / Low) и патчами.
```

## 3. Регистрация в `registry.json`

Чтобы расширение появилось в общем каталоге Klodex, добавьте запись о нём в корневой файл `registry.json`.

### Секции `registry.json`:

```json
{
  "version": "1.2.0",
  "updatedAt": "2026-10-19",
  "categories": [
    { "id": "architecture", "name": "Архитектура и Аудит" },
    { "id": "code", "name": "Разработка и Код" },
    { "id": "security", "name": "Безопасность" },
    { "id": "ops", "name": "SRE и Инциденты" },
    { "id": "writing", "name": "Текст и Документация" },

  ],
  "skills": [
    {
      "id": "clean-architecture",
      "name": "Clean Architecture Guard",
      "category": "architecture",
      "version": "1.0.0",
      "author": "your-github-username",
      "description": "Контроль границ слоев архитектуры и чистоты доменной логики.",
      "triggers": ["архитектура", "слои", "clean architecture"],

      "tags": ["security", "audit"]
    }
  ]
}
```

## 4. Как протестировать расширение локально

Вам не нужно отправлять Pull Request, чтобы проверить работу своего скилла. Klodex поддерживает локальную разработку расширений из коробки:

### Вариант 1: Для конкретного проекта (Project-Level)
Положите файл прямо в рабочую папку вашего проекта:
- Для скилла: `.klodex/skills/<name>/SKILL.md` (или `.klodex/skills/<name>.md`)
- Для промпта: `.klodex/prompts/<type>/<name>.md`

*Скилл автоматически применится только для этого проекта.*

### Вариант 2: Глобально для всех проектов (User-Level)
Положите файл в домашнюю директорию настроек Klodex:
- macOS / Linux: `~/.config/klodex/skills/` и `~/.config/klodex/prompts/`
- Windows: `%USERPROFILE%\.config\klodex\skills\` и `%USERPROFILE%\.config\klodex\prompts\`

Откройте Klodex — ваше расширение мгновенно отобразится в каталоге с бейджем «Установлено локально».

## 5. Правила публикации (Contributing Guidelines)

Перед отправкой Pull Request убедитесь, что расширение соответствует стандартам качества сообщества:

1. **Фокус и польза**: Расширение должно решать реальную инженерную проблему, а не содержать абстрактную воду.
2. **Отсутствие вредоносного кода**: Запрещены промпты для обхода защит сторонних сервисов, спама, атак или нарушения приватности.
3. **Чистый Markdown**: Валидный Frontmatter, отсутствие битых ссылок и спецсимволов, ломающих JSON-парсер.
4. **Валидный `registry.json`**: Проверьте синтаксис JSON перед коммитом (`bun -e "JSON.parse(await Bun.file('registry.json').text())"`).

### Шаги отправки:
1. Сделайте **Fork** репозитория `lonestill/klodex-skills`.
2. Создайте тематическую ветку: `git checkout -b feat/my-new-skill`.
3. Добавьте файл скилла/промпта и зарегистрируйте его в `registry.json`.
4. Закоммитьте изменения и отправьте Pull Request в ветку `main`.
5. После ревью ваш скилл будет опубликован и появится у всех пользователей Klodex!
